# 05 蓝牙（Intel AX200，USB 8087:0029）

## 最终配置

- Lilu 1.7.2 + **IntelBluetoothFirmware / IntelBTPatcher 2.5.3**（[lshbluesky 分支](https://github.com/lshbluesky/IntelBluetoothFirmware/releases)，上游 2.4.0 不支持 Tahoe）+ BlueToolFixup 2.7.2
- 加载顺序：IntelBluetoothFirmware → IntelBTPatcher → BlueToolFixup
- NVRAM（`Add` 和 `Delete` 两处都要写，保证每次开机重写）：
  ```
  bluetoothExternalDongleFailed   = <00>
  bluetoothInternalControllerInfo = <00 × 14 字节>
  ```
- **Tahoe 上不用 USB 映射**（见下面的坑）。

## 坑 1：第一次开蓝牙失败（地址为空，bluetoothd 反复崩溃）

系统信息里蓝牙显示 `Address: NULL`、`State: Off`，bluetoothd 不停重启。加上上面两个 NVRAM 项后正常，显示 `Chipset: THIRD_PARTY_DONGLE`。

## 坑 2：USB 映射让整个控制器消失

蓝牙在 XHC2（pcidebug 4:0:4）的 USB2 3 号口。Sequoia 时期自制了 `USBMap-XHC2.kext` 把这个口标成内置（类型 255），当时正常。

**升级到 Tahoe 后，这份映射会让 XHC2 开机就被关闭**：蓝牙模块、这个控制器上的两个 Hub 全部消失，IntelBluetoothFirmware 也不再加载。`ocvalidate` 校验完全通过，但运行时就是不兼容。关掉映射后一切恢复，蓝牙不需要标成内置也能用。

教训：静态校验通过 ≠ 运行时兼容；USB 映射要在当前系统版本上按实际端口重新做，不能照搬旧的。

## 坑 3：BLE 键盘打字中掉线（11-16 ~ 11-17）

### 现象
- BLE 键盘能配对、能打字，用几分钟到半小时就在**打字过程中**断开（不是空闲休眠）。
- 断开后系统可能还显示"已连接"，但 `hidutil list` 里已经没有键盘。
- 切换蓝牙开关或重启 bluetoothd 能暂时恢复，过一会儿又复现。

### 看日志

```bash
/usr/bin/log show --last 30m --style compact --predicate 'process == "bluetoothd" AND (eventMessage CONTAINS "LE ConnManager disconnection complete" OR eventMessage CONTAINS "LE Link Ready" OR eventMessage CONTAINS "LE Connection Parameters Updated")'
```

**断开原因码 = 700 + HCI 错误码（十进制）**。可以用 702 验证：取消正在进行的连接时返回 702，正好对应 HCI 0x02。

| 日志 | HCI | 含义 | 对应现象 |
|---|---|---|---|
| 708 | 0x08 Connection Timeout | 超过监督超时（约 2.16 秒）没收到对方的包 | 打字中掉线 |
| 762 | 0x3E Connection Failed to be Established | 发出连接后，对方前 6 个连接事件都没回应。日志里连上约 190ms 就断（≈ 6 × 30ms） | 掉线后反复重连失败 |

紧跟在 762 后面的 `Failed to encrypt connection STATUS 634` 只是连带结果：加密请求刚发出链路就断了（日志里 `encryptionPending 1`）。**不是配对密钥坏了，不用删配对。**

### 逐项排除

| 试过的 | 结果 | 结论 |
|---|---|---|
| 切蓝牙开关 / 重启 bluetoothd | 暂时恢复，之后复现 | 不是根治 |
| 重启电脑（控制器全新） | 开机第一次连接就 762 | 不是"控制器卡在异常状态" |
| 键盘断电重开 | 仍然连续 762 | 不是键盘状态卡住 |
| 重新配对 | 连上约 4 分钟又 708 | 不是配对密钥 |
| 关闭 Wi‑Fi | 照样 708 | 不是 Wi‑Fi 共存干扰 |
| 同一键盘接另一台 Windows 电脑 | 用了一年没问题 | 键盘本身没问题 |
| **IntelBluetoothFirmware / IntelBTPatcher 2.5.0 → lshbluesky 2.5.3** | 见下 | 重连修好了，掉线还在 |

### 升级到 2.5.3 之后（11-17 实测）

| | 2.5.0 | 2.5.3 |
|---|---|---|
| 首次连接 | 经常连续几十次 762 才连上，甚至连不上 | 第一次就连上 |
| 连上后多久掉一次（708） | 约 4～30 分钟 | 第一次观察是约 41 分钟（样本还少） |
| 掉线后重连 | 连续几十次 762，几分钟连不回来，要手动开关蓝牙 | **约 5 秒自动恢复**（一次 762 后就 Link Ready） |

结论：**2.5.3 明显改善了重连，但没有消除打字中的 708 超时掉线**。之后几个小时里又出现了多次掉线，有时一连几次，个别时候重连又会卡住，需要手动开关蓝牙。拔掉插在同一个 USB 控制器（XHC2）上的 USB 3 U 盘后照样掉线，所以也不是 USB 3 干扰。还没排除的可能是这台主机 AX200 的射频 / 天线（同一把键盘在**另一台** Windows 电脑上正常，不能证明本机硬件没问题）。

## 最终方案：CH582 蓝牙转 USB 接收器（绕开 AX200）

既然问题出在"Mac 这一侧的蓝牙"，干脆不用它：用一块 **CH582**（沁恒 BLE 5.3 + USB 单片机，开发板几十块钱）做一个接收器，作为 BLE 主机去连键盘，再以 **USB 有线键盘**的身份插到电脑上。

```
BLE 键盘  ──蓝牙──▶  CH582 接收器  ──USB HID──▶  Mac
                    (HOGP 主机)       (macOS 看到的就是普通 USB 键盘, 免驱)
```

### 好处

- AX200、Intel 蓝牙驱动、macOS 蓝牙协议栈**全部不参与**，黑苹果蓝牙的坑一次绕开。
- 接收器可以用 USB 延长线放到键盘旁边，射频距离只有几十厘米。
- 是 USB 键盘，所以在 **OpenCore 引导菜单、BIOS、恢复模式**里也能用（蓝牙键盘在这些地方用不了）。
- 不需要改 EFI、不受 macOS 版本升级影响。

### 固件要点

- **BLE 主机 + HID over GATT 客户端**：扫描键盘 → Just Works 配对绑定 → 发现 HID 服务 → 读 Report Map 和各报告的 Report Reference → 订阅输入报告；绑定信息和 GATT 句柄缓存在 Flash，断线自动回连，回连后不必重新发现服务。
- **报告描述符透传**：USB 键盘接口直接用键盘自己的 Report Map（首次配对后存 Flash，之后上电立即枚举），多媒体键、全键无冲等不做翻译、原样支持。
- **Boot 协议**：USB 接口声明为 Boot 键盘，BIOS/UEFI 切到 boot 协议时，让键盘也切到 boot 模式。
- 大写锁定等 LED 回传；断线时向电脑发"全部松开"，防止按键卡住；USB 挂起时按键远程唤醒。
- 另有一个厂商 HID 接口用于日志和命令；配了一个 **WebHID 网页上位机**（Chrome/Edge 打开即用），可以列出附近设备、手动选择要配对的键盘、看连接状态和信号强度。
- 基于带 USB OTA bootloader 的 boot+app 工程，第一次用 WCH ISP 烧录，之后通过 USB 直接升级，不用按 BOOT 键。

### 上板时踩的坑（CH58x 通用）

1. **ISP 库要求 4 字节对齐的缓冲区**：`GetMACAddress()` / `GET_UNIQUE_ID()` / `EEPROM_READ()` 按 32 位写入。直接把 `bleConfig_t.MacAddr` 这种结构体中间的字段传进去，会在启动时触发 HardFault（`mcause = 6`，store address misaligned）。先读到 `__attribute__((aligned(4)))` 的临时数组再拷贝。
2. **SDK 默认的 HardFault 处理会把芯片复位成"上电复位"**：bootloader 的"连续启动失败"计数因此不起作用，崩溃的固件会无限重启。调试时自己覆盖 `HardFault_Handler`，把 `mcause/mepc/mtval/sp/ra` 写进 Data-Flash 再复位，下次启动读出来，用 `riscv-none-embed-addr2line` 定位。
3. **Data-Flash 擦除单位是 4KB**：BLE 协议栈的绑定信息（SNV）在 0x7E00，所在的 0x7000 整块都不要再放别的数据，否则擦除时会互相覆盖。
4. **自动配对别"见 HID 就连"**：附近的蓝牙遥控器、自拍按钮也会广播 HID 服务。只自动连声明了**键盘外观**（0x03C1）的设备，或信号很强的 HID 设备；配对失败的设备暂时拉黑。
5. 第一次进 ISP 时芯片对命令不响应（只回零长度包），重新按住 BOOT 插一次、一识别到就马上烧录即可。
6. 厂商 HID 通道的日志要做成**非阻塞**的：macOS 上没有程序读这个接口时，阻塞式发送会卡住主循环、拖垮 BLE 协议栈。

### 结果（11-17）

接收器与键盘配对成功（信号约 -49 dBm），macOS 识别为 USB 键盘，打字正常。长时间是否还会掉线仍在观察：如果接收器也掉线，说明问题在键盘模块或射频环境；如果不掉，就证实问题在本机的 AX200 / macOS 蓝牙驱动。

固件：[ch582-ble-kbd-dongle](https://github.com/fenghelao/ch582-ble-kbd-dongle)（整理中，暂未公开）。

lshbluesky 分支在 2.5.0 之后陆续修复了 Tahoe 上的 BLE 设备问题（2.5.0‑d2 / d3），更新了包括 AX200 在内的 Intel 蓝牙固件（2.5.1），并修复了 LE 连接卡在等待数据长度事件的问题（2.5.2）。上游有人反馈过同样的"键盘短暂显示已连接，随后被 macOS 断开"（[PR #446](https://github.com/OpenIntelWireless/IntelBluetoothFirmware/pull/446)、[#460](https://github.com/OpenIntelWireless/IntelBluetoothFirmware/issues/460)）。

### 其他观察（没当成根因）
- 键盘是只支持基础 BLE 特性的模块（Remote Features `01 00…`，不支持数据长度扩展和 2M PHY）。
- 键盘每 30 秒请求一次 20–25ms / latency 20 / 2100ms 的参数，macOS 一直拒绝，实际用 15ms / latency 22 / 2160ms。断开原因是超时而不是对端主动断开，所以没把它当根因。

### 实时监控掉线（写入文件，便于对时间）
```bash
/usr/bin/log stream --style compact --predicate 'process == "bluetoothd" AND (eventMessage CONTAINS "disconnection complete" OR eventMessage CONTAINS "LE Link Ready")' | tee -a ~/bt-events.log
```
升级与回滚脚本见 [`tools/bluetooth/`](../tools/bluetooth/)。
