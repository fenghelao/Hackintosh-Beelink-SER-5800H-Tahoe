# 07 维护与救急

## 屏蔽系统更新

NootedRed 的修复依赖特定系统版本（见 [02](02-显卡-NootedRed.md)），一次小更新就可能让显卡重新卡死。

```bash
sudo softwareupdate --schedule off
sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate AutomaticCheckEnabled -bool false
sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate AutomaticDownload -bool false
sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate AutomaticallyInstallMacOSUpdates -bool false
sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate CriticalUpdateInstall -bool false
sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate ConfigDataInstall -bool false
```

更彻底的做法：在 `/etc/hosts` 末尾屏蔽系统更新服务器（先备份原文件）：

```
# block macOS updates
0.0.0.0 gdmf.apple.com
0.0.0.0 swscan.apple.com
0.0.0.0 swdist.apple.com
0.0.0.0 swquery.apple.com
```

副作用：系统更新、安全响应更新、XProtect 等后台安全数据都不会再更新；App Store 的应用更新不受影响。
恢复：删掉 hosts 里这几行，再 `sudo softwareupdate --schedule on`。

## 改 EFI 的固定流程

1. 挂载 EFI：`diskutil list` 找到 EFI 分区，`sudo diskutil mount diskXs1`。注意挂载点按卷名来，例如卷名是 `SYSTEM` 就挂在 `/Volumes/SYSTEM`，不一定是 `/Volumes/EFI`。
2. **完整备份**整个 `EFI` 文件夹，逐文件核对哈希值。
3. 在副本上修改，用对应版本的 `ocvalidate` 校验。
4. 复制回 EFI 分区，再逐文件比对。
5. 改完重启前，确认有能启动的 U 盘。

## 确认是从哪个 EFI 启动的

```bash
nvram 4D1FDA02-38C7-4A6A-9CC6-4BCCA8B30102:boot-path
```
带 `USB(...)` 是 U 盘，带 `NVMe(...)` 是内置盘。曾经升级后第一次开机是从 U 盘上那套旧 EFI 启动的（SIP 全开、NootedRed 旧版），1.5 小时内显卡卡死 35 次，差点误判成系统问题。

## 开不了机

1. 插上启动 U 盘，开机按 **F7**，选 U 盘的 UEFI 启动项。
2. U 盘上保留一套能启动的 EFI，以及内置盘 EFI 的完整副本。
3. 进系统后挂载内置盘 EFI，用副本整个覆盖回去。

## 从 GitHub 下载很慢 / 文件损坏

可以用镜像下载，然后和 GitHub API 返回的 sha256 核对：

```bash
curl -sSL https://api.github.com/repos/<owner>/<repo>/releases/latest | python3 -c 'import json,sys; [print(a["name"], a.get("digest")) for a in json.load(sys.stdin)["assets"]]'
shasum -a 256 下载的文件.zip
```
